# dsh-desktop-shell 0.1.3 Finalization Report

> Title: **dsh-desktop-shell 0.1.3 Finalization Report**
> Date: 2026-08-16

## 1. Release

```text
Version: 0.1.3
Status: Accepted stable baseline
```

`0.1.3` is the current **stable baseline** of the DesktopShell window chrome.
It has passed real Windows on-machine validation by the user (see §6) and is
frozen: window-chrome runtime behavior will not be changed again unless a
concrete regression is found.

## 2. Root problems fixed (0.1.1 → 0.1.3)

### 0.1.1 — taskbar / Alt+Tab icon regression

0.1.1 hid the native title-bar icon by setting the BrowserWindow icon to a
fully transparent `assets/icon-window.ico`. On Windows the title-bar icon and
the taskbar / Alt+Tab icon come from the same `WM_SETICON`, so the transparent
icon also broke the taskbar / Alt+Tab icon.

### 0.1.2 — icon fixed, but header collision and unusable drag

0.1.2 restored the real black icon (`assets/icon-black.ico`) and switched to
`titleBarStyle: "hidden"` + `titleBarOverlay`, but:

- the Window Controls Overlay buttons floated over the DSH page, which still
  started at `top: 0` — the DSH session header (Session log) and the Windows
  controls shared the same physical area;
- dragging relied on a 4px `-webkit-app-region: drag` strip that was present
  in the source but not practically usable by a real user.

### 0.1.3 — Desktop Caption Safe Area

0.1.3 introduced a dedicated DesktopShell caption area above the DSH content:

```text
BrowserWindow
├── Desktop Caption Safe Area
│   ├── drag lane
│   └── native Windows controls
└── DSH Web UI
```

The DSH page now starts **below** the caption, so Windows controls and DSH
header UI no longer share the same physical area, and the whole caption strip
is the (≈32px) drag region.

## 3. Final Window Architecture

```text
BrowserWindow viewport
├── 32px Desktop Caption Safe Area
│   ├── practical draggable lane
│   └── native Windows min / max / restore / close
│
└── DSH Web content
    ├── Session Header
    │   └── Session log / other utilities
    ├── Conversation
    └── Composer
```

Key property:

```text
Windows Controls  and  DSH Web UI  do NOT share the same physical area.
```

Geometry is driven by one source of truth (`lib/electron/chrome.js`):
`CAPTION_HEIGHT_PX = 32` simultaneously sets the `titleBarOverlay.height`, the
drag-lane height, and the DSH content top inset
(`body { padding-top }` + `#root { height: calc(100vh - 32px) }`), so the
three can never drift apart.

## 4. Icon Architecture

```text
Desktop shortcut  → assets/icon-black.ico
BrowserWindow     → assets/icon-black.ico
Windows taskbar   → assets/icon-black.ico
Alt+Tab           → assets/icon-black.ico
```

`assets/icon-window.ico` (the transparent window-icon workaround) is deleted
and its generator code is removed; it must not be restored.

## 5. Failure Isolation (unchanged)

- `desktop-shell` / `desktop-app` are installed `disabled: true`; plain
  `dsh web` never activates Desktop rows and never touches the Electron path.
- Desktop App Mode is enabled per launch only via
  `--patch launch/desktop-app.patch.yml`.
- Launcher / Electron-runtime / Electron-child / desktop-mode activation
  failures leave no persistent state; plain `dsh web` stays unaffected.
- DesktopShell remains a peer-level plugin; no other plugin depends on it.

## 9. Future maintenance / Known follow-up

Non-blocking, deferred (P2 maintenance — not a 0.1.3 release blocker):

```text
Consider adding explicit diagnostic logging or a safe fallback when
caption CSS / drag-lane injection fails.
```

`applyCaptionChrome()` currently treats `insertCSS` / `executeJavaScript`
failures as best-effort (silently swallowed). This is acceptable for 0.1.3
(user-verified) and was intentionally NOT changed during finalization to avoid
re-opening an accepted runtime; a future maintenance release (e.g. 0.1.4) may
add diagnostics/fallback.
